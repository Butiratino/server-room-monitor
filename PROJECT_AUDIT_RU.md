## Плата и официальные источники

Для маркировки **HTIT-WB32LAF V4.3** найдена точная официальная схема. Это **Heltec WiFi LoRa 32 V4**, а не WiFi Kit 32. По схеме используется ESP32-S3R2. LoRa для текущей задачи не требуется.

- Схема именно V4.3: https://resource.heltec.cn/download/WiFi_LoRa_32_V4/Schematic/HTIT-WB32LAF_V4.3.pdf
- Официальная распиновка семейства V4: https://resource.heltec.cn/download/WiFi_LoRa_32_V4/Pinmap/V4_pinmap.png
- Datasheet соседней ревизии V4.3.1: https://resource.heltec.cn/download/WiFi_LoRa_32_V4/datasheet/WiFi_LoRa_32_V4.3.1_Datasheet.pdf
- Документация семейства: https://docs.heltec.org/en/node/esp32/wifi_lora_32/index.html

В datasheet V4.3.1 дисплей указан как SSD1315 128x64. Текущий проект использует SSD1306-совместимый драйвер; работу на конкретном экземпляре нужно проверить. Не переносить распиновку с V2/V3 или WiFi Kit 32.

## Подключение датчика

Следующая таблица является рекомендацией по свободным GPIO из схемы, а не заводской инструкцией Heltec для этого датчика. Подключать при отключённом USB и аккумуляторе.

| Модуль датчика | Heltec V4 | Пояснение |
| --- | --- | --- |
| VCC / VIN | 3V3, J3 контакт 2 или 3 | Для первого запуска использовать 3,3 В |
| GND | GND, J3 контакт 1 | Общая земля |
| SDA / SDI | GPIO4, J3 контакт 15 | Предлагаемая SDA датчика |
| SCL / SCK | GPIO6, J3 контакт 17 | Предлагаемая SCL датчика |
| CS / CSB, если выведен | 3V3 | Выбор I2C для шестиконтактного модуля |
| SDO, если выведен | GND | Выбор адреса 0x76; при 3V3 адрес 0x77 |

Нумерация J3 соответствует официальной картинке, а не номеру GPIO. На pin map плата показана OLED к наблюдателю и USB снизу. В этой ориентации J3 слева, GND снизу. Перед подключением сверить надписи на своей плате и модуле; для окончательной проверки полезны фото обеих сторон.

Для четырёхконтактного модуля CS/SDO могут быть уже соединены на плате датчика. Адрес определить сканированием 0x76/0x77. У шестиконтактного модуля не оставлять CSB и SDO плавающими. Проверить схему конкретного модуля и наличие подтяжек SDA/SCL к 3,3 В. Не подавать 5 В на GPIO ESP32-S3.

OLED остаётся на GPIO17 (SDA), GPIO18 (SCL), GPIO21 (RESET), GPIO36 (Vext control). Предлагаемый датчик должен использовать другой аппаратный контроллер I2C, например I2C_NUM_1; текущая прошивка его ещё не создаёт. GPIO5 не выбран из-за использования в вариантах радиотракта Heltec. GPIO19/20 заняты USB, GPIO8-14 связаны с LoRa.

Управление Vext нужно проверить на конкретной ревизии: в официальных материалах есть расхождение по полярности. Исходная программа включает его уровнем LOW. Для датчика используется постоянный 3V3, не Vext.

## Библиотеки

- OLED: уже объявлена `chill-sam/ssd1306`, lock фиксирует 1.1.2. Компонент должен скачаться ESP-IDF Component Manager при успешной конфигурации; локальная загрузка сейчас не подтверждена. Источник: https://components.espressif.com/components/chill-sam/ssd1306/versions/1.1.2/readme
- Датчик: сначала определить BME280 или BMP280 чтением регистра chip ID 0xD0: 0x60 для BME280, 0x58 для BMP280. Оба измеряют температуру, влажность есть только у BME280.
- Возможный драйвер обоих чипов: `esp-idf-lib/bmp280` 1.0.7, https://components.espressif.com/components/esp-idf-lib/bmp280 . Перед добавлением проверить его I2C backend и совместимость с IDF 6.1: нельзя смешивать legacy и новый I2C-драйверы в одном приложении. Если backend legacy, использовать подходящий драйвер на новом API либо адаптацию Bosch SensorAPI.
- Wi-Fi, HTTPS, JSON и хранилище: штатные компоненты ESP-IDF `esp_wifi`, `esp_netif`, `esp_event`, `esp_http_client`, `mbedtls`, `json`/cJSON и `nvs_flash`. Telegram-библиотека не обязательна: достаточно HTTPS Bot API sendMessage.
- Не устанавливать Arduino-библиотеки Adafruit/UniversalTelegramBot в этот C/ESP-IDF проект.

## План дальнейшей работы

Это план этапов, не утверждённая спецификация алгоритма тревог. Пороговые температуры и период оповещений нужно согласовать перед реализацией.

1. Завершить установку ESP-IDF 6.1 для esp32s3 на D: со всеми нужными подмодулями и инструментами. Перенести настройки VS Code. Проверка: `idf.py --version`, затем `idf.py set-target esp32s3` и `idf.py build` в ESP-IDF-терминале; исправления исходников делать только по фактическим ошибкам.
2. Проверить OLED без датчика: подключить плату USB-кабелем с линиями данных, выбрать её порт, прошить исходный пример и проверить текст/переводы строк. Не стирать существующую прошивку до согласия владельца.
3. Подключить датчик по таблице. Создать вторую I2C-шину, проверить адрес и chip ID, подключить совместимый драйвер, читать температуру с проверкой ошибок. Проверка: правдоподобные показания в Serial, плавная реакция на нагрев, корректная ошибка при отключении датчика.
4. Заменить USB-терминал на экран температуры. Показывать температуру, состояние датчика и связи; при сбое не выдавать старое значение за актуальное. Проверка: обновление экрана без мерцания, явный статус отсутствующего датчика.
5. Добавить Wi-Fi и Telegram sendMessage по HTTPS с проверкой сертификата и синхронизацией времени. Обрабатывать отсутствие сети, таймауты, HTTP 429 и ошибки API; сетевые запросы не должны останавливать опрос и экран.
6. Согласовать смысл повышения/снижения: уведомления о каждом значимом изменении либо тревога при выходе за допустимый диапазон и уведомление о восстановлении. Для серверной рекомендуется второй вариант с гистерезисом, подтверждением устойчивого превышения и ограничением частоты сообщений. Конкретные значения не заданы.
7. Протестировать тревоги искусственными последовательностями температур: пересечение порога, колебания около порога без спама, восстановление, сбой датчика, потеря Wi-Fi и возвращение связи. Затем провести длительную проверку в реальном месте установки и сравнение с контрольным термометром.

Токен Telegram и Wi-Fi пароль не коммитить, не выводить в логи и не передавать в общую переписку. Для конфигурации предусмотреть локальное исключённое из Git хранилище/файл, а не публичные константы. Прямой Telegram с платы не сможет сообщить о полном отключении питания или сети: для такого контроля нужен внешний heartbeat-наблюдатель.

Датчик размещать вдали от регулятора питания, ESP32 и горячего выхлопа оборудования, если измеряется температура воздуха серверной. Обеспечить вентиляцию и выбрать репрезентативное место измерения. Один самодельный узел не заменяет промышленную систему аварийного мониторинга.
