# Независимая проверка BMP280

Это отдельный экспериментальный ESP-IDF-проект для проверки программной гипотезы. Он не использует OLED, `main/bmp280_temperature.c` или алгоритм измерений основного проекта.

## Библиотеки

Версии зафиксированы в manifest и `dependencies.lock`:

- `esp-idf-lib/bmp280` 1.0.7
- `esp-idf-lib/i2cdev` 2.1.2
- `esp-idf-lib/esp_idf_lib_helpers` 1.4.0
- ESP-IDF 6.1.0, ESP32-S3, Flash 16 МБ

Загруженные библиотечные исходники не изменялись. Инициализация и расчёт выполняются функциями библиотеки `bmp280_init_default_params`, `bmp280_init` и `bmp280_read_float`. Используется её normal mode, oversampling температуры и давления x4, filter off и standby 250 мс. В descriptor указаны прежние GPIO4/GPIO6, I2C_NUM_1, адрес 0x76, скорость 100 кГц и внутренние подтяжки. I2Cdev автоматически выбрал новый I2C master backend для ESP-IDF 6.1.

## Запуск

Открыть эту папку как отдельный проект в VS Code либо терминал PowerShell в `D:\Oled1\hardware_checks\bmp280_reference`. В обычном терминале предварительно активировать окружение:

```powershell
. D:\Espressif\Activate-Oled1.ps1
idf.py build
idf.py -p COM4 flash
idf.py -p COM4 monitor
```

Закрывать монитор через Ctrl+] перед другими операциями с COM4. Команда flash заменяет приложение на плате. Тест не управляет OLED, поэтому по экрану его состояние определить нельзя.

## Полученный результат

Независимый тест собран, прошит и проверен: получено восемь последовательных отчётов, ни одного с допустимой температурой. Представительный отчёт:

```json
{"type":"bmp280_reference","library":"esp-idf-lib/bmp280@1.0.7","chip_id":88,"temperature_c":-134.10,"pressure_pa":16767067.00,"valid_temperature":false,"calibration":[27388,25691,50],"raw":[255,255,192,0,0,0],"status":0,"control":111,"errors":[0,0,0]}
```

- ID=88 (0x58) и калибровка совпали с результатами собственного драйвера.
- Сырые байты температуры вновь равны `00 00 00`.
- `-134.10 C` является результатом пересчёта некорректного ADC, а не температурой воздуха; он вне рабочего диапазона BMP280 -40..85 C.
- Библиотечный ESP_OK подтверждает успешные транзакции, но не физическую достоверность измерения. Поэтому wrapper отдельно указывает `valid_temperature:false`.
- Контрольный регистр 111 (0x6F) соответствует библиотечному normal mode, T/P oversampling x4.
- Получение отчётов проверено; тест получения достоверной температуры НЕ пройден.

Результат показывает, что сбой не специфичен для собственного драйвера температуры или OLED. Однако оба варианта используют ту же плату, модуль, питание и SDK/I2C backend; поломка или подделка датчика этим экспериментом не доказана. Следующий полезный шаг: проверка питания на самом модуле и сравнительная проверка с заведомо исправным датчиком/другой аппаратной платформой.

После эксперимента на плату возвращается основной монитор с безопасным `Sensor error`; для повторения reference-теста нужно снова выполнить flash из этой папки. Основной проект и его зависимости не заменяются этими библиотеками.
